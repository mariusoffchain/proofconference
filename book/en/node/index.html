Proof of Work · Chapter 16

Running your own node

In brief

Without your own node, your wallet asks someone else's server about your money. A node is your own copy of Bitcoin's rules and ledger: it checks every block and every transaction itself, so you trust nobody's answer. It protects your privacy, and it strengthens the network. It needs a small always-on computer, a large SSD and a few days of patience. It is not a miner, and it earns nothing.

The problem

When you open a wallet app, it needs to know your balance. It does not have the ledger, so it asks a server: "what happened on these addresses?" That server belongs to the wallet's maker, or to an unknown volunteer.

Two things follow. First, the server learns which addresses are yours, all of them, together with your IP address. The separate wallets and fresh addresses from chapter 14 are grouped again, in somebody's logs. Second, you must believe the answer. If the server is wrong, offline or dishonest, your wallet shows you what it was told.

For small amounts this is a reasonable compromise, and most people start this way. But it is a strange ending for a system designed so that nobody has to be trusted. With your own node, the question never leaves your home.

How it works

A node is a computer running Bitcoin software, most often Bitcoin Core (other implementations exist, such as Bitcoin Knots). It downloads the whole ledger, from the first block in 2009, and verifies every transaction against the rules: no coin spent twice, no coin created from nothing, never more than 21 million. It then keeps doing this for every new block, about every ten minutes. This is the meaning of "don't trust, verify".

Your node accepts only what follows the rules. If thousands of people do the same, the rules of Bitcoin are simply whatever their nodes enforce. No company, miner or government can change them for you.

A node is not a miner. It uses little electricity and earns nothing. It also does not hold your coins: your keys stay in your wallet or signing device.

Realistic requirements: a small computer that stays on, a 1 to 2 TB SSD (the ledger is several hundred gigabytes and grows), a normal home connection, and a few days for the first synchronisation.

A pruned node is a lighter option: it verifies everything but keeps only the most recent blocks, so it fits on a small disk. The trade-off is that most wallet server software needs the full ledger.

Choose your route

All routes run the same Bitcoin software underneath. They differ in how much is done for you.

Route What it is Strengths Trade-offs
Bitcoin Core on your everyday computer The reference software, open source, from bitcoincore.org Free, the simplest start, includes its own wallet Not always on, takes disk space on your main machine
Umbrel A home server system with an app store. Runs on your own hardware, or on a device the company sells The most polished interface, one-click apps Made by one company. Free for personal use, but its licence is not open source (no commercial reuse)
Start9 (StartOS) An open source server system. Runs on your own hardware, or on a server the company sells Strong focus on privacy and self-hosting, good documentation Made by one company. A little more to learn at the start
RaspiBlitz An open source community project for the Raspberry Pi No company involved, strong Lightning tools More technical, some work on the command line
MyNode A node system for small computers, with a free community edition and a paid premium edition Simple web interface, many Bitcoin apps Made by a small company, some features reserved for the paid edition
The manual route Debian or Ubuntu Linux, then Bitcoin Core, then an Electrum server (electrs or Fulcrum), by following a guide You understand every part. Nothing hidden, fully open source Slow, command line only. For learners who enjoy it

Umbrel and Start9 are also general home servers, which connects with chapter 10: the same box can host your files and your passwords.

A reasonable setup for most people: try Bitcoin Core on your computer to see what a node is, then move to a dedicated small computer with the platform whose trade-offs suit you.

A word on Lightning nodes

The same platforms let you install a Lightning node (LND or Core Lightning) in one click. Treat it as a later project. A Lightning node holds real funds in channels, on a machine that is always online. Channels need their own backups, regular attention and an understanding of what happens if the disk fails. Restoring an old backup the wrong way can even cost you the funds in a channel. A Bitcoin node alone can break without any loss: you simply synchronise again. A Lightning node cannot. Learn with small amounts, and only after the rest of this chapter is routine.

Step by step

The example uses a platform with an app store, such as Umbrel or StartOS. RaspiBlitz and MyNode follow the same order.

  1. Choose the hardware. A used mini PC or a recent Raspberry Pi with 8 GB of memory, a 1 to 2 TB SSD from a known brand, and a network cable to your router.
  2. Install the platform by following its official guide, and set a strong, unique password (chapter 2).
  3. Install the Bitcoin app and let it synchronise. It takes from one day to a week, depending on the hardware. Do not interrupt it.
  4. Install an Electrum server app (electrs or Fulcrum). It builds an index so that wallets can ask your node questions. This takes more hours.
  5. Connect your wallet. In Sparrow, BlueWallet or Nunchuk, open the server or network settings and enter the address of your own Electrum server instead of the public one. Zeus is different: it connects to a Lightning node, for later.
  6. Reach it from outside your home over Tor or a private VPN (see chapter 10). The platforms provide a Tor address for this.
  7. Keep it updated, and keep your seed backups separate from the node. The node needs no seed, and should never see one.

Mistakes to avoid

  • Using a cheap SD card or USB stick as the main disk. A node writes constantly. These fail within months and can corrupt the data. Use a real SSD.
  • No power protection. A sudden power cut can damage the database and cost you days of synchronisation. Always shut down from the interface, and consider a small battery backup (UPS).
  • Thinking the node holds your coins. It does not, unless you run Lightning. If the node dies, your bitcoin is untouched: your seed is what matters.
  • Exposing it to the internet. Do not open ports on your router to reach the dashboard. Use Tor or a VPN.
  • Giving up during the first synchronisation. It looks stuck for days. It is not. It is verifying more than fifteen years of transactions, once.
  • Downloading software from the wrong place. Get Bitcoin Core only from bitcoincore.org, and each platform from its official website.
